# Augusto Gonzalez

A bilingual engineering portfolio built with React, TypeScript, Vite, and pnpm.

## Run

Use Node 24 and pnpm 10.30.3.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Open the local URL printed by Vite. Use `?lang=es` to open the Spanish version. The language switch preserves the current section and stores your preference locally.

## Redesign preview

Open `/?preview=revision&lang=en` for the revised timeline, portrait, React/Next.js and Web3 sections. `#story/mcp` opens the engineering walkthrough; `#mobile` opens the separate app library. Each app opens its contribution story before an optional demo.

This is the interactive layout review stage. The previous site remains at `/` until the replacement direction is reviewed. The preview brief is [src/preview/brief.md](src/preview/brief.md). Its factual copy is in `src/preview/content.ts`; brand asset sources are recorded in `public/brands/sources.json`. The access console is generated by `scripts/build-console.mjs` and passes the Anatomy geometry audit. It represents responsibilities, not a production deployment topology.

## Verify

```sh
pnpm check
pnpm exec playwright install chrome
pnpm test:e2e
pnpm format:check
```

`check` runs Oxlint, TypeScript, model tests, the Anatomy geometry audit, and the production build. Playwright checks desktop and mobile interactions, language persistence, PDF downloads, reduced motion, WebGL fallback, and accessibility. `pnpm preview` serves the production build.

Commit messages follow Conventional Commits. Husky runs commitlint locally; CI validates commits in pull requests. For example: `feat: add portfolio project`.

## Content and behavior

- `src/content/translations.ts`: English and Spanish copy.
- `src/content/projects.ts`: project metadata and verified store links.
- `src/demos/`: four local product recreations. Their data is fictional; their controls do not call production services. Switching projects or selecting Reset clears a demo.
- `src/system/`: the Seen request model and its SVG/WebGL renderer. A repeated request uses the cache; Expire cache forces another provider call. Timing illustrates sequence, not production latency.
- `scripts/build-machine.mjs`: the geometry source. Builds regenerate `src/system/generated.ts` and `docs/machine-parts.json` after validating all solids.
- `public/cv/`: copies of the supplied PDFs. Their source files were not modified.
- `public/audio/`: an original 30-second ambient sample, generated for this portfolio. Playback requires a click. The offline control simulates the product state; it does not install a service worker.

The system module loads near its section. Animation stops offscreen and in hidden tabs. Reduced motion and unavailable WebGL retain the complete request model and SVG rendering. Contact uses email; there is no form, backend, analytics, or credential setup.

See [content evidence](docs/content-evidence.md), [store-link audit](docs/store-links.md), [design system](DESIGN.md), and [skill revisions](docs/skill-sources.json).

## Deploy

The GitHub Pages workflow is manual. In repository Settings → Pages, select **GitHub Actions** as the source. Then run **Actions → Deploy portfolio → Run workflow** from the branch to publish. It checks and builds the site before uploading `dist`.

This repository is the root user site (`augustoalegon.github.io`), so Vite uses `/` as its base. Update Vite's base and the root-relative asset URLs before moving it to a project subpath. No deployment occurs during local development.

The small Anatomy rendering kit is vendored under `vendor/anatomy/` with its upstream license. Portfolio geometry and demo interfaces are original recreations, not exported app source or screenshots.
